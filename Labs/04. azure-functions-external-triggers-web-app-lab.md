# Hands-on lab: Trigger Azure Functions from an external web app

In this lab, you expose the functions from the earlier labs to an external browser-based system: a small HTML web app with forms.

The web app calls:

1. The approval workflow start endpoint from Lab 02 or Lab 03.
2. The approval decision endpoint that raises a Durable Functions external event.
3. The Durable Functions status URL returned by the start endpoint.

The goal is not to build a production front end. The goal is to understand what must be in place when an external system, such as a web app, Power App, partner portal, or webhook sender, invokes your Azure Functions workflow.

## Audience and duration

- Audience: workshop attendees who completed Lab 02. Lab 03 is recommended.
- Duration: 60 minutes.
- Skill level: basic HTML, browser developer tools, HTTP, and Azure Functions.

## Learning objectives

By the end of this lab, you will be able to:

- Trigger an HTTP Azure Function from an external browser app.
- Configure local CORS for cross-origin browser calls.
- Configure Azure Function App CORS for a deployed external client.
- Use the Durable Functions status URL returned by `CreateCheckStatusResponseAsync`.
- Submit a human approval decision from a web form into a running Durable orchestration.
- Explain why function keys are a lab convenience, not a complete browser-app security model.

## Prerequisites

Complete Lab 02 first. Lab 03 is preferred because it adds idempotent request IDs and decision IDs.

You should already have:

- A local Azure Functions project named `DurableApprovalLab`.
- A working `POST /api/approvals` endpoint.
- A working `POST /api/approvals/{instanceId}/decision` endpoint.
- Azurite running for local Durable Functions state.
- Azure Functions Core Tools installed.
- Visual Studio Code.
- A browser.

You also need one way to serve static HTML locally from `http://localhost:5500`.

Recommended option:

- Install the **Live Server** extension for Visual Studio Code.

Alternative:

- Use any local static web server you already have. Keep the origin as `http://localhost:5500` or adjust the CORS commands in this lab.

> Instructor note: CORS is a browser protection. Server-to-server callers such as Logic Apps, API Management, backend services, and many webhook senders do not rely on browser CORS. This lab uses a browser app because it makes external integration visible and easy to test.

## Architecture

```mermaid
flowchart LR
    A[External web app<br/>localhost:5500] -->|POST /api/approvals| B[StartApproval HTTP function]
    B --> C[Durable orchestration]
    C --> D[Activities]
    C -->|WaitForExternalEvent| E[approval_response]
    A -->|GET statusQueryGetUri| F[Durable status endpoint]
    A -->|POST /api/approvals/{instanceId}/decision| G[SubmitDecision HTTP function]
    G -->|RaiseEventAsync| E
```

```html
    const state = {
      baseUrl: "http://localhost:7071/api",
      functionKey: "",
      statusUrl: "",
      instanceId: ""
    };

    const byId = (id) => document.getElementById(id);

    function writeOutput(value) {
      byId("output").textContent = typeof value === "string"
        ? value
        : JSON.stringify(value, null, 2);
    }

    function loadConfig() {
      state.baseUrl = localStorage.getItem("approvalClient.baseUrl") || state.baseUrl;
      state.functionKey = localStorage.getItem("approvalClient.functionKey") || "";
      byId("baseUrl").value = state.baseUrl;
      byId("functionKey").value = state.functionKey;
    }

    function saveConfig() {
      state.baseUrl = byId("baseUrl").value.trim().replace(/\/+$/, "");
      state.functionKey = byId("functionKey").value.trim();
      localStorage.setItem("approvalClient.baseUrl", state.baseUrl);
      localStorage.setItem("approvalClient.functionKey", state.functionKey);
      writeOutput({ message: "Connection settings saved.", baseUrl: state.baseUrl });
    }

    function apiUrl(path) {
      return `${state.baseUrl}${path}`;
    }

    function headers(includeJson = true) {
      const result = {};
      if (includeJson) {
        result["content-type"] = "application/json";
      }

      if (state.functionKey) {
        result["x-functions-key"] = state.functionKey;
      }

      return result;
    }

    async function readResponse(response) {
      const text = await response.text();
      let body = text;

      try {
        body = text ? JSON.parse(text) : null;
      } catch {
        body = text;
      }

      return {
        ok: response.ok,
        status: response.status,
        statusText: response.statusText,
        headers: {
          idempotencyResult: response.headers.get("x-idempotency-result")
        },
        body
      };
    }

    async function sendJson(url, payload) {
      const response = await fetch(url, {
        method: "POST",
        headers: headers(),
        body: JSON.stringify(payload)
      });

      return await readResponse(response);
    }

    async function startApproval() {
      const payload = {
        requestId: byId("requestId").value.trim(),
        requester: byId("requester").value.trim(),
        item: byId("item").value.trim(),
        amount: Number(byId("amount").value),
        timeoutMinutes: Number(byId("timeoutMinutes").value),
        businessJustification: byId("businessJustification").value,
        simulateNotificationFailure: byId("simulateNotificationFailure").checked
      };

      const result = await sendJson(apiUrl("/approvals"), payload);
      const body = result.body || {};

      state.instanceId = body.id || payload.requestId;
      state.statusUrl = body.statusQueryGetUri || "";

      byId("instanceId").value = state.instanceId;
      byId("statusUrl").value = state.statusUrl;

      writeOutput({
        request: payload,
        response: result,
        nextStep: payload.amount > 100
          ? "Submit a decision before the timeout expires."
          : "Low-value requests should auto-approve. Check status."
      });
    }

    async function getStatus() {
      const statusUrl = byId("statusUrl").value.trim();
      if (!statusUrl) {
        writeOutput("No status URL is available. Start an approval first.");
        return;
      }

      const response = await fetch(statusUrl, {
        method: "GET",
        headers: headers(false)
      });

      writeOutput(await readResponse(response));
    }

    async function submitDecision() {
      const instanceId = byId("instanceId").value.trim();
      if (!instanceId) {
        writeOutput("No instance ID is available. Start an approval first.");
        return;
      }

      const payload = {
        decisionId: byId("decisionId").value.trim(),
        approved: byId("approved").value === "true",
        approver: byId("approver").value.trim(),
        comments: byId("decisionComments").value
      };

      const result = await sendJson(apiUrl(`/approvals/${encodeURIComponent(instanceId)}/decision`), payload);
      writeOutput({ request: payload, response: result });
    }

    byId("saveConfigButton").addEventListener("click", saveConfig);
    byId("startButton").addEventListener("click", startApproval);
    byId("statusButton").addEventListener("click", getStatus);
    byId("decisionButton").addEventListener("click", submitDecision);

    loadConfig();
  </script>

```

## Exercise 4: Start a workflow from the external form

In the web app:

1. Keep **Functions API base URL** set to `http://localhost:7071/api`.
2. Leave **Function key** empty for the local Lab 02 or Lab 03 approval endpoints.
3. Set **Request ID** to `REQ-WEB-1001`.
4. Set **Amount** to `250`.
5. Select **Start approval**.

Expected result:

- The response status is `202 Accepted`.
- The response body contains a Durable Functions status URL.
- The **Instance ID** field is populated.
- The **Status query URL** field is populated.

Select **Get status**.

Expected result:

- The runtime status is usually `Running`.
- The custom status shows that the workflow is waiting for approval.

> Instructor note: If you completed Lab 03, run the same request twice with the same `requestId`. The second request should return the existing orchestration instead of creating a duplicate workflow.

## Exercise 5: Submit a human decision from the web app

In the web app:

1. Confirm **Instance ID** is populated.
2. Set **Decision ID** to `DEC-WEB-1001`.
3. Keep **Decision** set to **Approve**.
4. Select **Submit decision**.

Expected result:

- The response status is `202 Accepted`.
- The response body confirms that the decision was submitted.

Select **Get status** again.

Expected result:

- The runtime status becomes `Completed`.
- The output contains an approval result.

If you completed Lab 03, select **Submit decision** again with the same `decisionId`.

Expected result:

- The response should not create a second business decision.
- The response includes the idempotency behavior from Lab 03.

## Exercise 6: Test validation and browser error handling

Use the same browser app to trigger controlled error cases.

### Missing request ID

Clear **Request ID**, then select **Start approval**.

Expected result with Lab 03:

- The response status is `400 Bad Request`.
- The response body explains that `requestId` is required.

### Missing decision ID

Start a valid request with a new `requestId`, for example `REQ-WEB-1002`.

Clear **Decision ID**, then select **Submit decision**.

Expected result with Lab 03:

- The response status is `400 Bad Request`.
- The response body explains that `decisionId` is required.

### CORS failure

Stop the Functions host and restart it without the CORS option:

```powershell
func start
```

Refresh the web app and select **Start approval**.

Expected result:

- The browser blocks the request.
- The Functions host may show no application-level error because the browser stops the response from being exposed to JavaScript.
- Browser developer tools show a CORS error.

Restart with CORS enabled before continuing:

```powershell
func start --cors http://localhost:5500
```

## Exercise 7: Call the deployed Azure Function App

Use this exercise only if you deployed the Durable approval workflow in Lab 02 or Lab 03.

Set your deployment variables:

```powershell
$resourceGroup = "<resource-group-name>"
$functionApp = "<function-app-name>"
$webOrigin = "http://localhost:5500"
```

Add the browser app origin to the Function App CORS settings:

```powershell
az functionapp cors add `
  --resource-group $resourceGroup `
  --name $functionApp `
  --allowed-origins $webOrigin
```

Confirm the CORS setting:

```powershell
az functionapp cors show `
  --resource-group $resourceGroup `
  --name $functionApp `
  --query allowedOrigins `
  -o table
```

Set the web app **Functions API base URL** to:

```text
https://<function-app-name>.azurewebsites.net/api
```

Select **Save connection settings**.

Start and approve a workflow from the browser app.

Expected result:

- The browser app can call the deployed Function App.
- The Durable status URL uses the deployed Function App host name.
- The orchestration completes in Azure.

> Instructor note: Lab 02 and Lab 03 use anonymous approval endpoints for workshop speed. If you change the functions to `AuthorizationLevel.Function`, retrieve a host key and paste it into the web app's **Function key** field.

Retrieve a host key only for lab testing:

```powershell
az functionapp keys list `
  --resource-group $resourceGroup `
  --name $functionApp `
  --query "hostKeys.default" `
  -o tsv
```

Do not paste production secrets into browser apps.

## Exercise 9: Production discussion

Use this checklist to discuss what would change before a real external app goes live.

| Topic | Lab implementation | Production consideration |
| --- | --- | --- |
| Browser client | Static HTML form on localhost | Host the front end in an approved web platform and manage release/versioning. |
| Authentication | Anonymous endpoints or optional function key | Prefer Microsoft Entra ID, API Management, Easy Auth, or a server-side facade. Do not treat function keys as user identity. |
| Secret handling | Optional function key pasted into the page | Do not put production secrets in public browser code. Use delegated auth or backend token exchange. |
| CORS | Allow `http://localhost:5500` | Allow only known production origins. Avoid broad wildcard origins for authenticated browser apps. |
| Idempotency | Lab 03 uses `requestId` and `decisionId` | Define key ownership, retention, duplicate semantics, and storage. |
| Status polling | Browser polls `statusQueryGetUri` manually | Add backoff, timeout handling, user-friendly states, or push notifications. |
| Observability | Browser shows raw JSON | Add correlation IDs, Application Insights queries, dashboards, and support runbooks. |
| API boundary | Browser calls Function App directly | Consider API Management for policies, throttling, auth, schemas, and versioned APIs. |

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Browser shows a CORS error | Function host was not started with the browser origin, or Azure CORS does not include the origin | Restart local Functions with `func start --cors http://localhost:5500`, or add the deployed origin with `az functionapp cors add`. |
| Browser page uses `file://` | The page was opened directly from disk | Serve the page from Live Server or another local static server. |
| `404 Not Found` when starting approval | Base URL is wrong or missing `/api` | Use `http://localhost:7071/api` locally or `https://<app>.azurewebsites.net/api` in Azure. |
| `401 Unauthorized` | Endpoint uses function-level authorization and no key was supplied | Paste a lab host key into **Function key**, or switch the workshop endpoint back to anonymous. |
| Status URL is empty | The start request failed before Durable Functions returned management URLs | Check the response body, fix validation errors, and start again. |
| Status stays `Running` | Amount is greater than 100 and no decision was submitted | Submit a decision before the timeout expires. |
| Decision returns accepted but status does not change | Wrong instance ID, already completed workflow, or stale browser state | Copy the instance ID from the latest start response and check the Functions host logs. |

```powershell
az functionapp cors remove `

```
