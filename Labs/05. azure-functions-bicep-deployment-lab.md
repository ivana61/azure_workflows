# Lab 05 - Deploy Azure Functions and Durable Functions with Bicep

## Goal

In this final lab, you will deploy the Azure resources for the Durable Functions approval workflow by using Bicep, then publish the existing .NET 10 isolated worker Function App to the deployed infrastructure.

By the end of this lab, you will have:

- A repeatable Bicep template for the Function App infrastructure.
- A Flex Consumption Function App configured for .NET 10 isolated worker.
- Azure Storage configured for Functions and Durable Functions runtime state.
- Application Insights connected to a Log Analytics workspace.
- A user-assigned managed identity with storage and monitoring permissions.
- CORS configured so the external web app from Lab 04 can call the deployed API.
- A published Durable Functions app running in Azure.

> Production note: This lab keeps the HTTP approval endpoints easy to call for workshop speed. For production, place a stronger API boundary in front of the Function App, such as Microsoft Entra ID authentication, API Management, Easy Auth, or a server-side facade. Do not expose anonymous workflow mutation endpoints to untrusted callers.

## Architecture

The Bicep template deploys these resources:

| Resource | Purpose |
| --- | --- |
| Resource group | Workshop deployment boundary and cleanup scope. |
| Storage account | Required by Azure Functions and Durable Functions for host, queue, table, and blob state. |
| Blob container | Deployment package storage used by Flex Consumption. |
| Log Analytics workspace | Stores Application Insights telemetry. |
| Application Insights | Captures requests, dependencies, exceptions, and traces. |
| User-assigned managed identity | Lets the Function App access Storage and Application Insights without storage keys. |
| Role assignments | Grants least-privilege storage and monitoring access to the managed identity. |
| Flex Consumption plan | Serverless Linux hosting plan for Azure Functions. |
| Function App | Runs the .NET 10 isolated worker Durable Functions app. |

The deployment separates infrastructure deployment from code deployment:

1. Bicep creates and configures Azure resources.
2. Azure Functions Core Tools publishes the compiled Function App code.

This mirrors common real-world delivery pipelines where infrastructure and application code are validated separately but released together.

## Exercise 1: Prepare the infrastructure folder

Open a terminal in the Durable Functions project folder. If your project is not in this exact path, adjust the command.

```powershell
Set-Location C:\Labs\DurableApprovalLab
```

Create an `infra` folder:

```powershell
New-Item -ItemType Directory -Path .\infra -Force
```

Create this file:

```text
infra\main.bicep
```

Add the following Bicep:

```bicep
targetScope = 'resourceGroup'

@description('Primary region for all Azure resources.')
param location string = resourceGroup().location

@description('Unique token used for resource name generation.')
@minLength(3)
param resourceToken string = toLower(uniqueString(subscription().id, resourceGroup().id, location))

@description('Globally unique Function App name.')
param appName string = 'func-durable-${resourceToken}'

@description('Browser origin allowed to call the Function App API. Use the Lab 04 static web app origin.')
@minLength(1)
param externalWebOrigin string = 'http://localhost:5500'

@description('Target .NET isolated worker runtime version.')
// The workshop targets .NET 10. Add future runtime values when Flex Consumption supports them.
@allowed([
  '10'
])
param functionAppRuntimeVersion string = '10'

@description('The maximum scale-out instance count limit for the Flex Consumption app.')
// Flex Consumption uses 40 as the minimum allowed maximum scale-out limit.
@minValue(40)
@maxValue(1000)
param maximumInstanceCount int = 100

@description('The memory size of each Flex Consumption instance in MB.')
@allowed([
  2048
  4096
])
param instanceMemoryMB int = 2048

var storageAccountName = 'st${resourceToken}'
var deploymentStorageContainerName = 'app-package-${take(toLower(appName), 32)}-${take(resourceToken, 7)}'

var storageBlobDataOwnerRoleId = 'b7e6dc6d-f1e8-4753-8033-0f276bb0955b'
var storageQueueDataContributorRoleId = '974c5e8b-45b9-4653-ba55-5f855dd0fb88'
var storageTableDataContributorRoleId = '0a9a7e1f-b9d0-4cc4-a60d-0319b160aaa3'
var monitoringMetricsPublisherRoleId = '3913510d-42f4-4e42-8a64-420c390055eb'

resource logAnalytics 'Microsoft.OperationalInsights/workspaces@2023-09-01' = {
  name: 'log-${resourceToken}'
  location: location
  properties: {
    sku: {
      name: 'PerGB2018'
    }
    retentionInDays: 30
    features: {
      searchVersion: 1
    }
  }
}

resource applicationInsights 'Microsoft.Insights/components@2020-02-02' = {
  name: 'appi-${resourceToken}'
  location: location
  kind: 'web'
  properties: {
    Application_Type: 'web'
    WorkspaceResourceId: logAnalytics.id
    DisableLocalAuth: true
  }
}

resource storage 'Microsoft.Storage/storageAccounts@2023-05-01' = {
  name: storageAccountName
  location: location
  kind: 'StorageV2'
  sku: {
    name: 'Standard_LRS'
  }
  properties: {
    accessTier: 'Hot'
    allowBlobPublicAccess: false
    allowSharedKeyAccess: false
    minimumTlsVersion: 'TLS1_2'
    supportsHttpsTrafficOnly: true
    publicNetworkAccess: 'Enabled'
    networkAcls: {
      bypass: 'AzureServices'
      defaultAction: 'Allow'
    }
  }

  resource blobServices 'blobServices' = {
    name: 'default'

    resource deploymentContainer 'containers' = {
      name: deploymentStorageContainerName
      properties: {
        publicAccess: 'None'
      }
    }
  }
}

resource managedIdentity 'Microsoft.ManagedIdentity/userAssignedIdentities@2023-01-31' = {
  name: 'uai-func-${resourceToken}'
  location: location
}

resource storageBlobDataOwner 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(storage.id, managedIdentity.id, storageBlobDataOwnerRoleId)
  scope: storage
  properties: {
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', storageBlobDataOwnerRoleId)
    principalId: managedIdentity.properties.principalId
    principalType: 'ServicePrincipal'
  }
}

resource storageQueueDataContributor 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(storage.id, managedIdentity.id, storageQueueDataContributorRoleId)
  scope: storage
  properties: {
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', storageQueueDataContributorRoleId)
    principalId: managedIdentity.properties.principalId
    principalType: 'ServicePrincipal'
  }
}

resource storageTableDataContributor 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(storage.id, managedIdentity.id, storageTableDataContributorRoleId)
  scope: storage
  properties: {
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', storageTableDataContributorRoleId)
    principalId: managedIdentity.properties.principalId
    principalType: 'ServicePrincipal'
  }
}

resource monitoringMetricsPublisher 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(applicationInsights.id, managedIdentity.id, monitoringMetricsPublisherRoleId)
  scope: applicationInsights
  properties: {
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', monitoringMetricsPublisherRoleId)
    principalId: managedIdentity.properties.principalId
    principalType: 'ServicePrincipal'
  }
}

resource appServicePlan 'Microsoft.Web/serverfarms@2024-04-01' = {
  name: 'plan-${resourceToken}'
  location: location
  kind: 'functionapp'
  sku: {
    tier: 'FlexConsumption'
    name: 'FC1'
  }
  properties: {
    reserved: true
  }
}

resource functionApp 'Microsoft.Web/sites@2024-04-01' = {
  name: appName
  location: location
  kind: 'functionapp,linux'
  identity: {
    type: 'UserAssigned'
    userAssignedIdentities: {
      '${managedIdentity.id}': {}
    }
  }
  properties: {
    serverFarmId: appServicePlan.id
    httpsOnly: true
    siteConfig: {
      minTlsVersion: '1.2'
      ftpsState: 'Disabled'
      cors: {
        allowedOrigins: [
          externalWebOrigin
        ]
        supportCredentials: false
      }
    }
    functionAppConfig: {
      deployment: {
        storage: {
          type: 'blobContainer'
          value: '${storage.properties.primaryEndpoints.blob}${deploymentStorageContainerName}'
          authentication: {
            type: 'UserAssignedIdentity'
            userAssignedIdentityResourceId: managedIdentity.id
          }
        }
      }
      runtime: {
        name: 'dotnet-isolated'
        version: functionAppRuntimeVersion
      }
      scaleAndConcurrency: {
        maximumInstanceCount: maximumInstanceCount
        instanceMemoryMB: instanceMemoryMB
      }
    }
  }

  resource appSettings 'config' = {
    name: 'appsettings'
    properties: {
      AzureWebJobsStorage__accountName: storage.name
      AzureWebJobsStorage__credential: 'managedidentity'
      AzureWebJobsStorage__clientId: managedIdentity.properties.clientId
      APPLICATIONINSIGHTS_CONNECTION_STRING: applicationInsights.properties.ConnectionString
      APPLICATIONINSIGHTS_AUTHENTICATION_STRING: 'ClientId=${managedIdentity.properties.clientId};Authorization=AAD'
      FUNCTIONS_EXTENSION_VERSION: '~4'
    }
  }
}

output functionAppName string = functionApp.name
output functionAppUrl string = 'https://${functionApp.properties.defaultHostName}'
output storageAccountName string = storage.name
output managedIdentityPrincipalId string = managedIdentity.properties.principalId
```

## Exercise 3: Create a resource group

List regions that support Flex Consumption:

```powershell
az functionapp list-flexconsumption-locations --query "sort_by(@, &name)[].{Region:name}" -o table
```

Pick a supported region close to you. The examples below use `westeurope`.

```powershell
$location = "westeurope"
$random = Get-Random -Minimum 100000 -Maximum 999999
$resourceGroup = "rg-durable-bicep-$random"

  --name $resourceGroup `
  --location $location
```

Keep these variables in the same terminal session. Later commands reuse them.

## Exercise 4: Preview the deployment with what-if

Expected result:

- No resources are deleted.
- The plan includes a Function App, Flex Consumption plan, Storage account, Application Insights, Log Analytics, managed identity, and role assignments.

## Exercise 5: Deploy the infrastructure

Deploy the Bicep template:

```powershell
$deployment = az deployment group create `
  --resource-group $resourceGroup `
  --template-file .\infra\main.bicep `
  --parameters appName=$functionApp externalWebOrigin=$webOrigin `
  | ConvertFrom-Json

$functionApp = $deployment.properties.outputs.functionAppName.value
$baseUrl = $deployment.properties.outputs.functionAppUrl.value
$principalId = $deployment.properties.outputs.managedIdentityPrincipalId.value

"Function App: $functionApp"
"Base URL: $baseUrl"
"Managed Identity Principal ID: $principalId"
```

Expected result:

- The deployment succeeds.
- `$baseUrl` is a fully qualified HTTPS URL such as `https://func-durable-bicep-123456.azurewebsites.net`.

> If the deployment fails while creating role assignments, confirm your Azure account can assign RBAC roles in the resource group or subscription. Contributor alone is not always enough for role assignment creation.

## Exercise 6: Inspect the deployed resources

Check the Function App:

```powershell
az functionapp show `
  --resource-group $resourceGroup `
  --name $functionApp `
  --query "{name:name, state:state, kind:kind, hostName:defaultHostName}" `
  -o table
```

Check the app settings that connect the Function App to Storage and Application Insights:

```powershell
az functionapp config appsettings list `
  --resource-group $resourceGroup `
  --name $functionApp `
  --query "[?starts_with(name, 'AzureWebJobsStorage') || starts_with(name, 'APPLICATIONINSIGHTS') || name == 'FUNCTIONS_EXTENSION_VERSION'].{Name:name, Value:value}" `
  -o table
```

Check CORS:

```powershell
az functionapp cors show `
  --resource-group $resourceGroup `
  --name $functionApp `
  --query allowedOrigins `
  -o table
```

Check role assignments for the managed identity:

```powershell
az role assignment list `
  --assignee $principalId `
  --resource-group $resourceGroup `
  --query "[].{Role:roleDefinitionName, Scope:scope}" `
  -o table
```

Expected result:

- CORS includes `http://localhost:5500`.
- The managed identity has Storage Blob Data Owner plus Storage Queue and Table Data Contributor roles.
- The managed identity has Monitoring Metrics Publisher access to Application Insights.

> Role assignment propagation can take a few minutes. If code deployment or runtime startup fails immediately after infrastructure deployment, wait two minutes and retry.

## Exercise 8: Test the deployed Durable Functions API

Submit an approval request:

```powershell
$requestId = "REQ-$(Get-Date -Format yyyyMMddHHmmss)"

$body = @{
  requestId = $requestId
  requester = "Adele Vance"
  item = "Bicep-deployed Durable Functions workflow"
  amount = 2500
  businessJustification = "Validate infrastructure as code deployment."
  timeoutMinutes = 5
} | ConvertTo-Json

$cloudResponse = Invoke-RestMethod `
  -Method POST `
  -Uri "$baseUrl/api/approvals" `
  -ContentType "application/json" `
  -Body $body

$cloudResponse | ConvertTo-Json -Depth 5
```

Expected result:

- The response includes an orchestration instance ID.
- The response includes a status query URL hosted on your deployed Function App.

Approve the workflow:

```powershell
$decision = @{
  decisionId = "DECISION-$requestId"
  approved = $true
  approver = "lab-instructor"
  comments = "Approved after Bicep deployment."
} | ConvertTo-Json

Invoke-RestMethod `
  -Method POST `
  -Uri "$baseUrl/api/approvals/$($cloudResponse.id)/decision" `
  -ContentType "application/json" `
  -Body $decision

Start-Sleep -Seconds 5
Invoke-RestMethod -Uri $cloudResponse.statusQueryGetUri | ConvertTo-Json -Depth 10
```

Expected result:

- The orchestration completes.
- The output shows the approved workflow result.

> If your project is still using the Lab 02 version of the code, the extra `requestId` and `decisionId` JSON fields should be ignored. If you completed Lab 03, those fields exercise the idempotency logic.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `az deployment group create` fails on role assignments | Your account cannot create RBAC assignments | Ask for User Access Administrator or Owner on the scope, or have an admin deploy the template. |
| Function App deploys but runtime fails to start | Managed identity permissions have not propagated yet | Wait a few minutes, then restart the Function App or republish. |
| `func azure functionapp publish` fails with runtime mismatch | The deployed runtime and local target framework do not match | Keep the project on `net10.0` and the deployed Bicep runtime on .NET isolated worker version `10`. |
| Browser app shows CORS errors | `externalWebOrigin` does not match the browser app origin | Redeploy the Bicep template with the correct origin, or add the origin with `az functionapp cors add`. |
| Approval API returns `404` | The code was not published, or the base URL is missing `/api` | Republish with Functions Core Tools and use `$baseUrl/api` in the web app. |
| Approval decision times out | The decision endpoint did not raise the expected Durable external event | Confirm the instance ID and decision payload, then check Application Insights traces. |
| Storage-related errors appear in logs | Durable Functions cannot access queues, tables, or blobs | Confirm the managed identity has Blob, Queue, and Table Data Contributor roles on the storage account. |

## Production improvement discussion

| Area | Lab implementation | Production direction |
| --- | --- | --- |
| Hosting | Flex Consumption plan | Keep Flex Consumption for event-driven workloads; use Premium only when you need features Flex does not cover. |
| Identity | User-assigned managed identity | Use managed identity consistently for Azure resource access. Avoid storage keys and connection strings where identity is supported. |
| Network access | Public Function App and Storage endpoints | Consider private endpoints, VNET integration, and approved egress paths. |
| API security | Anonymous or function-key HTTP endpoints | Use Microsoft Entra ID, API Management, Easy Auth, or a backend facade. |
| Browser CORS | Single localhost origin | Parameterize approved origins per environment. Avoid wildcard origins for authenticated apps. |
| Observability | Application Insights and Log Analytics | Add dashboards, alerts, correlation IDs, and runbooks. |
| Release process | Manual CLI commands | Move Bicep validation, what-if, deployment, and publish into CI/CD. |
| Environment separation | One workshop resource group | Use dev, test, and prod parameter files or pipeline variables. |
| Resilience | Durable retry/idempotency from Lab 03 | Add operational alerts for poison messages, retries, failed orchestrations, and dependency failures. |

## Key takeaways

- Bicep makes the Function App infrastructure repeatable and reviewable.
- Flex Consumption Function Apps require `functionAppConfig`, including deployment storage configuration.
- Durable Functions need reliable access to Storage queues, tables, and blobs.
- Managed identity reduces the need for secrets in app settings.
- Infrastructure deployment and code publishing are separate concerns.
- What-if should be part of the normal workflow before applying infrastructure changes.
