# Hands-on lab: Implement task processing logic with Azure Functions

This attendee guide is adapted from Microsoft AZ-204 Lab 02: "Implement task processing logic by using Azure Functions." It has been simplified so you can run it on your own machine without the Microsoft Learn hosted lab VM or `F:\Allfiles` path.

The lab has no AI component. You will create:

1. An HTTP-triggered function that echoes request content.
2. A timer-triggered function that runs on a schedule.
3. An HTTP-triggered function that reads a JSON file from Azure Blob Storage.
4. A deployment of the local Functions project to Azure.

Estimated time: 75-120 minutes, depending on how much Azure portal and local tooling setup is already done.

## Prerequisites

Each attendee needs:

- An Azure subscription where they can create a resource group, storage account, and Function App.
- Visual Studio Code.
- .NET 10 SDK.
- Azure Functions Core Tools v4.
- Azure CLI.
- `curl` or another HTTP client.

On Windows, the tools can be installed with:

```powershell
winget install Microsoft.AzureCLI
winget install Microsoft.Azure.FunctionsCoreTools
winget install Microsoft.DotNet.SDK.10
winget install Microsoft.VisualStudioCode
```

Validate the tools:

```powershell
az --version
func --version
dotnet --version
code --version
```

Sign in to Azure:

```powershell
az login
az account show
```

If you have access to multiple subscriptions, select the one you will use:

```powershell
az account set --subscription "<subscription-id-or-name>"
```

## Naming and setup conventions

Use these values throughout the lab, replacing `<alias>` with your initials or short name and `<unique>` with a random number or short string.

| Item | Suggested value |
| --- | --- |
| Resource group | `rg-azfunc-lab-<alias>` |
| Region | `westeurope` if available; otherwise choose another supported region |
| Storage account | `funcstor<alias><unique>` |
| Function App | `funclogic-<alias>-<unique>` |
| Local lab folder | `C:\Labs\AzFunctionsLab` |
| Local function project | `C:\Labs\AzFunctionsLab\func` |

Storage account names must be globally unique, 3-24 characters, lowercase letters and numbers only. Function App names must also be globally unique.

Create the local folders:

```powershell
New-Item -ItemType Directory -Force C:\Labs\AzFunctionsLab\func | Out-Null
Set-Location C:\Labs\AzFunctionsLab
```

## Lab scenario

In this lab, you implement simple task processing logic by using Azure Functions.

You will:

1. Create Azure resources for the lab.
2. Create a local Azure Functions project.
3. Build an HTTP-triggered function.
4. Build a timer-triggered function.
5. Build a function that uses a Blob Storage input binding.
6. Deploy the local project to Azure Functions.

## Exercise 1: Create Azure resources

### Task 1: Open the Azure portal

1. Open a browser.
2. Go to https://portal.azure.com.
3. Sign in with the Azure account you will use for this lab.

### Task 2: Create a resource group

You can create the resource group from the Azure portal or the Azure CLI.

Portal option:

1. In the Azure portal search box, search for **Resource groups**.
2. Select **Resource groups**.
3. Select **+ Create**.
4. Configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-azfunc-lab-<alias>` |
   | Region | `West Europe` or your chosen region |

5. Select **Review + create**.
6. Select **Create**.

CLI option:

```powershell
az group create `
  --name rg-azfunc-lab-<alias> `
  --location westeurope
```

### Task 3: Create an Azure Storage account

1. In the Azure portal search box, search for **Storage accounts**.
2. Select **Storage accounts**.
3. Select **+ Create**.
4. On the **Basics** tab, configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-azfunc-lab-<alias>` |
   | Storage account name | `funcstor<alias><unique>` |
   | Region | Same region as the resource group |
   | Primary service | Azure Blob Storage or default |
   | Performance | Standard |
   | Redundancy | Locally-redundant storage (LRS) |

5. Select **Review** or **Review + create**.
6. Select **Create**.
7. Wait for deployment to complete.
8. Select **Go to resource**.

Record the storage connection string:

1. In the storage account menu, under **Security + networking**, select **Access keys**.
2. Select **Show keys**.
3. Copy one of the **Connection string** values.
4. Save it temporarily somewhere safe, such as a local scratch note. You will paste it into `local.settings.json` later.

Important: The connection string contains a key. Do not commit it to source control or share it.

### Task 4: Create a Function App

1. In the Azure portal search box, search for **Function App**.
2. Select **Function App**.
3. Select **+ Create**.
4. If prompted to select a hosting option, choose **Consumption**. If your tenant only shows newer options, choose the closest serverless option available for .NET 10.
5. On the **Basics** tab, configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-azfunc-lab-<alias>` |
   | Function App name | `funclogic-<alias>-<unique>` |
   | Runtime stack | `.NET` |
   | Version | `.NET 10, isolated worker model` |
   | Region | Same region as the resource group |
   | Operating system | Linux |

6. On the **Storage** tab, select the storage account you created earlier.
7. Accept the defaults on the remaining tabs.
8. Select **Review + create**.
9. Select **Create**.
10. Wait for deployment to complete.

Checkpoint:

- You have a resource group.
- You have a storage account.
- You have a Function App.
- You have saved the storage account connection string for local development.

## Exercise 2: Configure a local Azure Functions project

### Task 1: Initialize the function project

Open PowerShell and run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func init --worker-runtime dotnet-isolated --target-framework net10.0 --force
```

This creates a local Azure Functions project using the .NET 10 isolated worker model.

### Task 2: Configure the storage connection string

Open the project in Visual Studio Code:

```powershell
code C:\Labs\AzFunctionsLab\func
```

In Visual Studio Code:

1. Open `local.settings.json`.
2. Find this setting:

   ```json
   "AzureWebJobsStorage": "UseDevelopmentStorage=true"
   ```

3. Replace `UseDevelopmentStorage=true` with the storage connection string you copied earlier.
4. Save the file.

The file should look similar to this, but with your actual connection string:

```json
{
  "IsEncrypted": false,
  "Values": {
    "AzureWebJobsStorage": "<your-storage-connection-string>",
    "FUNCTIONS_WORKER_RUNTIME": "dotnet-isolated"
  }
}
```

Important: `local.settings.json` contains secrets and should not be committed to source control.

### Task 3: Build and validate the project

Run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
dotnet build
```

Checkpoint:

- The build completes successfully.
- The project is ready for functions.

## Exercise 3: Create an HTTP-triggered function

### Task 1: Create the HTTP-triggered function

Run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func new --template "HTTP trigger" --name "Echo" --authlevel function
```

This creates a new function named `Echo`.

### Task 2: Write the function code

In Visual Studio Code:

1. Open `Echo.cs`.
2. Replace the entire file content with:

```csharp
using System.Net;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Azure.Functions.Worker.Http;
using Microsoft.Extensions.Logging;

namespace func
{
    public class Echo
    {
        private readonly ILogger _logger;

        public Echo(ILoggerFactory loggerFactory)
        {
            _logger = loggerFactory.CreateLogger<Echo>();
        }

        [Function("Echo")]
        public async Task<HttpResponseData> Run([HttpTrigger(AuthorizationLevel.Function, "get", "post")] HttpRequestData req)
        {
            _logger.LogInformation("C# HTTP trigger function processed a request.");

            var response = req.CreateResponse(HttpStatusCode.OK);
            response.Headers.Add("Content-Type", "text/plain; charset=utf-8");

            StreamReader reader = new StreamReader(req.Body);
            string requestBody = await reader.ReadToEndAsync();
            await response.WriteStringAsync(requestBody);

            return response;
        }
    }
}
```

3. Save the file.

### Task 3: Test the HTTP-triggered function locally

In PowerShell, start the Functions host:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func start --build
```

Leave this terminal running.

Open a second PowerShell terminal and test the function:

```powershell
curl.exe -X POST -i http://localhost:7071/api/echo -d "3"
curl.exe -X POST -i http://localhost:7071/api/echo -d "5"
curl.exe -X POST -i http://localhost:7071/api/echo -d "Hello"
curl.exe -X POST -i http://localhost:7071/api/echo -H "Content-Type: application/json" -d '{"msg":"Successful"}'
```

Expected result:

- The response body matches the value you sent.
- The function host logs show that the HTTP trigger processed the request.

When finished, return to the terminal running `func start` and press **Ctrl+C**.

Checkpoint:

- You created a basic function that echoes HTTP request content.

## Exercise 4: Create a timer-triggered function

### Task 1: Create the timer-triggered function

Run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func new --template "Timer trigger" --name "Recurring"
```

This creates a function named `Recurring`.

### Task 2: Review and update the timer schedule

In Visual Studio Code:

1. Open `Recurring.cs`.
2. Find the timer trigger schedule:

   ```csharp
   [TimerTrigger("0 */5 * * * *")]
   ```

3. Replace it with:

   ```csharp
   [TimerTrigger("0 */1 * * * *")]
   ```

4. Save the file.

The schedule expression `"0 */1 * * * *"` runs the function every minute.

The full file should look similar to:

```csharp
using System;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Extensions.Logging;

namespace func
{
    public class Recurring
    {
        private readonly ILogger _logger;

        public Recurring(ILoggerFactory loggerFactory)
        {
            _logger = loggerFactory.CreateLogger<Recurring>();
        }

        [Function("Recurring")]
        public void Run([TimerTrigger("0 */1 * * * *")] TimerInfo myTimer)
        {
            _logger.LogInformation($"C# Timer trigger function executed at: {DateTime.Now}");

            if (myTimer.ScheduleStatus is not null)
            {
                _logger.LogInformation($"Next timer schedule at: {myTimer.ScheduleStatus.Next}");
            }
        }
    }
}
```

### Task 3: Observe the timer function locally

Run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func start --build
```

Wait for at least one minute.

Expected result:

- The terminal shows a log entry for the `Recurring` function.
- A new log entry appears about once per minute.

When finished, press **Ctrl+C**.

Checkpoint:

- You created a function that runs automatically on a schedule.

## Exercise 5: Create a function that integrates with Blob Storage

In this exercise, you upload a JSON file to Blob Storage and create a function that reads it using a Blob input binding.

### Task 1: Upload sample content to Azure Blob Storage

In the Azure portal:

1. Go to **Resource groups**.
2. Open `rg-azfunc-lab-<alias>`.
3. Open your storage account, `funcstor<alias><unique>`.
4. In the storage account menu, under **Data storage**, select **Containers**.
5. Select **+ Container**.
6. Configure:

   | Setting | Value |
   | --- | --- |
   | Name | `content` |

7. Select **Create**.
8. Open the new `content` container.
9. Select **Upload**.
10. Browse to `C:\Labs\AzFunctionsLab\settings.json`.
11. Make sure **Overwrite if files already exist** is selected.
12. Select **Upload**.

Expected result:

- The `content` container contains a blob named `settings.json`.

CLI alternative:

```powershell
$storageConnectionString = "<your-storage-connection-string>"

az storage container create `
  --name content `
  --connection-string $storageConnectionString

az storage blob upload `
  --container-name content `
  --name settings.json `
  --file C:\Labs\AzFunctionsLab\settings.json `
  --connection-string $storageConnectionString `
  --overwrite
```

### Task 2: Create an HTTP-triggered function

Run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func new --template "HTTP trigger" --name "GetSettingInfo" --authlevel function
```

### Task 3: Register the Azure Storage extension

Run:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
dotnet add package Microsoft.Azure.Functions.Worker.Extensions.Storage --version 6.8.1
dotnet build
```

### Task 4: Write the function code with a Blob input binding

In Visual Studio Code:

1. Open `GetSettingInfo.cs`.
2. Replace the entire file content with:

```csharp
using System.Net;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Azure.Functions.Worker.Http;
using Microsoft.Extensions.Logging;

namespace func
{
    public class GetSettingInfo
    {
        private readonly ILogger _logger;

        public GetSettingInfo(ILoggerFactory loggerFactory)
        {
            _logger = loggerFactory.CreateLogger<GetSettingInfo>();
        }

        [Function("GetSettingInfo")]
        public HttpResponseData Run(
            [HttpTrigger(AuthorizationLevel.Function, "get", "post")] HttpRequestData req,
            [BlobInput("content/settings.json", Connection = "AzureWebJobsStorage")] string blobContent)
        {
            _logger.LogInformation("C# HTTP trigger function processed a request.");
            _logger.LogInformation($"{blobContent}");

            var response = req.CreateResponse(HttpStatusCode.OK);
            response.Headers.Add("Content-Type", "application/json; charset=utf-8");
            response.WriteString($"{blobContent}");

            return response;
        }
    }
}
```

3. Save the file.

### Task 5: Test the Blob-integrated function locally

Start the Functions host:

```powershell
Set-Location C:\Labs\AzFunctionsLab\func
func start --build
```

Leave this terminal running.

Open a second PowerShell terminal and call the function:

```powershell
curl.exe -X GET -i http://localhost:7071/api/GetSettingInfo
```

Expected result:

The response body contains:

```json
{
    "version": "0.2.4",
    "root": "/usr/libexec/mews_principal/",
    "device": {
        "id": "21e46d2b2b926cba031a23c6919"
    },
    "notifications": {
        "email": "joseph.price@contoso.com",
        "phone": "(425) 555-0162 x4151"
    }
}
```

When finished, return to the terminal running `func start` and press **Ctrl+C**.

Checkpoint:

- You created a function that reads a JSON file from Blob Storage.
- The function returns the JSON content over HTTP.

## Troubleshooting

### `func` is not recognized

Azure Functions Core Tools is not installed or not on your PATH.

Run:

```powershell
winget install Microsoft.Azure.FunctionsCoreTools
```

Close and reopen PowerShell, then try:

```powershell
func --version
```

### `dotnet build` fails

Check that .NET 10 is installed:

```powershell
dotnet --list-sdks
```

Install .NET 10 if needed:

```powershell
winget install Microsoft.DotNet.SDK.10
```

### Local function cannot connect to storage

Check `local.settings.json`.

Make sure:

- `AzureWebJobsStorage` contains the full storage connection string.
- The JSON file is valid.
- You did not accidentally add line breaks inside the connection string.

### `GetSettingInfo` returns an error

Check:

- The storage account has a container named `content`.
- The `content` container has a blob named `settings.json`.
- `local.settings.json` points to the same storage account.
- The Storage extension package was added successfully.

Run:

```powershell
dotnet list package
```

You should see `Microsoft.Azure.Functions.Worker.Extensions.Storage`.

### Deployment succeeds, but portal test fails

Check the Function App configuration:

1. In the Azure portal, open the Function App.
2. Go to **Settings** > **Environment variables** or **Configuration**.
3. Check that `AzureWebJobsStorage` exists.
4. Confirm it points to the storage account where you uploaded `content/settings.json`.

If needed, update the setting and restart the Function App.
