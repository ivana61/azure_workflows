# Hands-on lab: Implement task processing logic with Azure Logic Apps

This attendee guide mirrors the flow of Lab 01 (Azure Functions) but uses Azure Logic Apps instead of code. You will build the same processing scenarios — HTTP echo, recurring schedule, and Blob Storage integration — using the Logic Apps visual designer and built-in connectors.

The lab has no AI component. You will create:

1. An HTTP-triggered Logic App that echoes request content.
2. A recurrence-triggered Logic App that runs on a schedule.
3. An HTTP-triggered Logic App that reads a JSON file from Azure Blob Storage.
4. A review of monitoring and run history in the Azure portal.

Estimated time: 60-90 minutes, depending on how much Azure portal setup is already done.

## Prerequisites

Each attendee needs:

- An Azure subscription where they can create a resource group, storage account, and Logic App.
- A modern web browser (the Logic Apps designer runs in the Azure portal).
- Azure CLI (optional, for resource creation via command line).

On Windows, the Azure CLI can be installed with:

```powershell
winget install Microsoft.AzureCLI
```

Validate the tool:

```powershell
az --version
```

Sign in to Azure:

```powershell
az login
az account show
```

If you have access to multiple subscriptions, select the one you will use:

```powershell
az account set --subscription "<subscription-id-or-name>"
```

## Naming and setup conventions

Use these values throughout the lab, replacing `<alias>` with your initials or short name and `<unique>` with a random number or short string.

| Item | Suggested value |
| --- | --- |
| Resource group | `rg-logicapp-lab-<alias>` |
| Region | `westeurope` if available; otherwise choose another supported region |
| Storage account | `logicstor<alias><unique>` |
| Logic App (Echo) | `logic-echo-<alias>-<unique>` |
| Logic App (Recurring) | `logic-recurring-<alias>-<unique>` |
| Logic App (GetSettingInfo) | `logic-getsetting-<alias>-<unique>` |

Storage account names must be globally unique, 3-24 characters, lowercase letters and numbers only. Logic App names must also be globally unique.

## Lab scenario

In this lab, you implement simple task processing logic by using Azure Logic Apps — the same scenarios as the Azure Functions lab, but without writing code.

You will:

1. Create Azure resources for the lab.
2. Build an HTTP-triggered Logic App that echoes request content.
3. Build a recurrence-triggered Logic App that runs on a schedule.
4. Build a Logic App that reads from Blob Storage and returns the content.
5. Review run history and monitoring.

## Exercise 1: Create Azure resources

### Task 1: Open the Azure portal

1. Open a browser.
2. Go to https://portal.azure.com.
3. Sign in with the Azure account you will use for this lab.

### Task 2: Create a resource group

You can create the resource group from the Azure portal or the Azure CLI.

Portal option:

1. In the Azure portal search box, search for **Resource groups**.
2. Select **Resource groups**.
3. Select **+ Create**.
4. Configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-logicapp-lab-<alias>` |
   | Region | `West Europe` or your chosen region |

5. Select **Review + create**.
6. Select **Create**.

CLI option:

```powershell
az group create `
  --name rg-logicapp-lab-<alias> `
  --location westeurope
```

### Task 3: Create an Azure Storage account

1. In the Azure portal search box, search for **Storage accounts**.
2. Select **Storage accounts**.
3. Select **+ Create**.
4. On the **Basics** tab, configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-logicapp-lab-<alias>` |
   | Storage account name | `logicstor<alias><unique>` |
   | Region | Same region as the resource group |
   | Primary service | Azure Blob Storage or default |
   | Performance | Standard |
   | Redundancy | Locally-redundant storage (LRS) |

5. Select **Review** or **Review + create**.
6. Select **Create**.
7. Wait for deployment to complete.
8. Select **Go to resource**.

CLI option:

```powershell
az storage account create `
  --name logicstor<alias><unique> `
  --resource-group rg-logicapp-lab-<alias> `
  --location westeurope `
  --sku Standard_LRS
```

### Task 4: Upload sample content to Azure Blob Storage

> **Important:** To upload blobs using `--auth-mode login` (Azure CLI) or through the portal, your user account must have the **Storage Blob Data Contributor** role assigned on the storage account or the `content` container. You can assign this role in the portal under the storage account's **Access Control (IAM)** blade, or with the CLI:
>
> ```powershell
> az role assignment create `
>   --role "Storage Blob Data Contributor" `
>   --assignee "<your-azure-ad-email-or-object-id>" `
>   --scope "/subscriptions/<subscription-id>/resourceGroups/rg-logicapp-lab-<alias>/providers/Microsoft.Storage/storageAccounts/logicstor<alias><unique>"
> ```
>
> Wait 1-2 minutes for the role assignment to propagate before uploading.

In the Azure portal:

1. Open your storage account, `logicstor<alias><unique>`.
2. In the storage account menu, under **Data storage**, select **Containers**.
3. Select **+ Container**.
4. Configure:

   | Setting | Value |
   | --- | --- |
   | Name | `content` |

5. Select **Create**.
6. Open the new `content` container.
7. Select **Upload**.
8. Browse to `C:\Labs\LogicAppsLab\settings.json`.
9. Make sure **Overwrite if files already exist** is selected.
10. Select **Upload**.

CLI alternative:

```powershell
$storageAccountName = "logicstor<alias><unique>"

az storage container create `
  --name content `
  --account-name $storageAccountName `
  --auth-mode login

az storage blob upload `
  --container-name content `
  --name settings.json `
  --file C:\Labs\LogicAppsLab\settings.json `
  --account-name $storageAccountName `
  --auth-mode login `
  --overwrite
```

Checkpoint:

- You have a resource group.
- You have a storage account with a `content` container containing `settings.json`.

## Exercise 2: Create an HTTP-triggered Logic App (Echo)

In this exercise, you create a Logic App that receives an HTTP request and returns the request body as the response — the same behavior as the Echo function.

### Task 1: Create the Logic App resource

1. In the Azure portal search box, search for **Logic apps**.
2. Select **Logic apps**.
3. Select **+ Add**.
4. On the **Basics** tab, configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-logicapp-lab-<alias>` |
   | Logic App name | `logic-echo-<alias>-<unique>` |
   | Region | Same region as the resource group |
   | Plan type | **Consumption** |

5. Select **Review + create**.
6. Select **Create**.
7. Wait for deployment to complete.
8. Select **Go to resource**.

CLI option:

```powershell
az logic workflow create `
  --resource-group rg-logicapp-lab-<alias> `
  --location westeurope `
  --name logic-echo-<alias>-<unique> `
  --definition '{\"$schema\":\"https://schema.management.azure.com/providers/Microsoft.Logic/schemas/2016-06-01/workflowdefinition.json#\",\"contentVersion\":\"1.0.0.0\",\"triggers\":{},\"actions\":{}}'
```

### Task 2: Design the workflow

1. In the Logic App overview, select **Logic app designer** (or **Edit** if you see a blank template page).
2. If prompted to choose a template, select **Blank Logic App**.

#### Add the HTTP Request trigger

3. In the designer search box, search for **Request**.
4. Under **Triggers**, select **When a HTTP request is received**.
5. Leave the **Request Body JSON Schema** empty (we accept any content).

#### Add the Response action

6. Select **+ New step**.
7. Search for **Response**.
8. Select **Response** (under the **Request** connector).
9. Configure the Response action:

   | Setting | Value |
   | --- | --- |
   | Status Code | `200` |
   | Headers | Add a header: Key = `Content-Type`, Value = `text/plain; charset=utf-8` |
   | Body | Click in the Body field, then select **Dynamic content** > **Body** (from the trigger) |

10. Select **Save** in the toolbar.

### Task 3: Get the endpoint URL

After saving:

1. Select the **When a HTTP request is received** trigger in the designer.
2. Copy the **HTTP POST URL** that appears. This is the endpoint for your Logic App.
3. Save this URL — you will use it to test.

### Task 4: Test the HTTP-triggered Logic App

Open PowerShell and test the Logic App:

```powershell
$url = "<paste-your-logic-app-url-here>"

curl.exe -X POST -i $url -H "Content-Type: text/plain" -d "3"
curl.exe -X POST -i $url -H "Content-Type: text/plain" -d "5"
curl.exe -X POST -i $url -H "Content-Type: text/plain" -d "Hello"
curl.exe -X POST -i $url -H "Content-Type: application/json" -d '{\"msg\":\"Successful\"}'
```

Expected result:

- The response body matches the value you sent.
- HTTP status is 200 for each call.

### Task 5: Review run history

1. In the Azure portal, open your Logic App `logic-echo-<alias>-<unique>`.
2. In the Logic App menu, select **Overview**.
3. Under **Run history** (or **Runs history**), you should see successful runs for each test call.
4. Select one of the runs to see the input and output of each step.

Checkpoint:

- You created a Logic App that echoes HTTP request content.
- You verified it in the run history.

## Exercise 3: Create a recurrence-triggered Logic App

In this exercise, you create a Logic App that runs on a recurring schedule — equivalent to the timer-triggered function.

### Task 1: Create the Logic App resource

1. In the Azure portal, go to **Logic apps**.
2. Select **+ Add**.
3. On the **Basics** tab, configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-logicapp-lab-<alias>` |
   | Logic App name | `logic-recurring-<alias>-<unique>` |
   | Region | Same region as the resource group |
   | Plan type | **Consumption** |

4. Select **Review + create**.
5. Select **Create**.
6. Wait for deployment to complete.
7. Select **Go to resource**.

### Task 2: Design the workflow

1. In the Logic App overview, select **Logic app designer**.
2. If prompted, select **Blank Logic App**.

#### Add the Recurrence trigger

3. In the designer search box, search for **Recurrence**.
4. Under **Triggers**, select **Recurrence**.
5. Configure the trigger:

   | Setting | Value |
   | --- | --- |
   | Interval | `1` |
   | Frequency | `Minute` |

#### Add a Compose action (to log the current time)

6. Select **+ New step**.
7. Search for **Compose**.
8. Select **Compose** (under **Data Operations**).
9. In the **Inputs** field, enter the following expression:

   Click **Expression** tab in the dynamic content panel and type:

   ```
   concat('Logic App executed at: ', utcNow())
   ```

   Select **OK**.

10. Select **Save**.

### Task 3: Observe the recurrence Logic App

1. Wait 2-3 minutes.
2. In the Azure portal, open your Logic App `logic-recurring-<alias>-<unique>`.
3. Select **Overview**.
4. Under **Run history**, you should see a new run appearing approximately once per minute.
5. Select one of the runs to see the Compose action output, which shows the execution timestamp.

Expected result:

- A new run appears approximately every minute.
- The Compose action output shows a message like: `Logic App executed at: 2026-06-15T08:10:00.0000000Z`

### Task 4: Disable the Logic App

To avoid continuous execution (and potential charges on a Consumption plan):

1. In the Logic App **Overview**, select **Disable** in the toolbar.
2. The Logic App status changes to **Disabled**.

You can re-enable it later by selecting **Enable**.

Checkpoint:

- You created a Logic App that runs automatically on a schedule.
- You verified the recurring executions in run history.

## Exercise 4: Create a Logic App that integrates with Blob Storage

In this exercise, you create a Logic App that receives an HTTP request, reads a JSON file from Blob Storage, and returns its content — equivalent to the `GetSettingInfo` function.

### Task 1: Create the Logic App resource

1. In the Azure portal, go to **Logic apps**.
2. Select **+ Add**.
3. On the **Basics** tab, configure:

   | Setting | Value |
   | --- | --- |
   | Subscription | Your lab subscription |
   | Resource group | `rg-logicapp-lab-<alias>` |
   | Logic App name | `logic-getsetting-<alias>-<unique>` |
   | Region | Same region as the resource group |
   | Plan type | **Consumption** |

4. Select **Review + create**.
5. Select **Create**.
6. Wait for deployment to complete.
7. Select **Go to resource**.

### Task 2: Design the workflow

1. In the Logic App overview, select **Logic app designer**.
2. If prompted, select **Blank Logic App**.

#### Add the HTTP Request trigger

3. In the designer search box, search for **Request**.
4. Under **Triggers**, select **When a HTTP request is received**.
5. Set the **Method** to `GET` (click **Add new parameter** and select **Method**, then choose **GET**).

#### Add the Azure Blob Storage action

6. Select **+ New step**.
7. Search for **Azure Blob Storage**.
8. Under **Actions**, select **Get blob content (V2)**.
9. If prompted, create a connection to your storage account:

   | Setting | Value |
   | --- | --- |
   | Connection Name | `blobconnection` |
   | Authentication Type | **Access Key** |
   | Azure Storage Account name | `logicstor<alias><unique>` |
   | Azure Storage Account Access Key | Paste the access key from your storage account (find it under **Security + networking** > **Access keys** in the storage account blade) |

10. Select **Create**.
11. Configure the **Get blob content (V2)** action:

    | Setting | Value |
    | --- | --- |
    | Storage account name | **Use connection settings** (default) |
    | Blob path | `/content/settings.json` |
    | Infer content type | **Yes** |

#### Add the Response action

12. Select **+ New step**.
13. Search for **Response**.
14. Select **Response** (under the **Request** connector).
15. Configure the Response action:

    | Setting | Value |
    | --- | --- |
    | Status Code | `200` |
    | Headers | Add a header: Key = `Content-Type`, Value = `application/json; charset=utf-8` |
    | Body | Click in the Body field, then select **Dynamic content** > **File Content** (from the Get blob content step) |

16. Select **Save**.

### Task 3: Get the endpoint URL

After saving:

1. Select the **When a HTTP request is received** trigger in the designer.
2. Copy the **HTTP GET URL** that appears.
3. Save this URL.

### Task 4: Test the Blob-integrated Logic App

Open PowerShell and call the Logic App:

```powershell
$url = "<paste-your-logic-app-url-here>"

curl.exe -X GET -i $url
```

Expected result:

The response body contains:

```json
{
    "version": "0.2.4",
    "root": "/usr/libexec/mews_principal/",
    "device": {
        "id": "21e46d2b2b926cba031a23c6919"
    },
    "notifications": {
        "email": "joseph.price@contoso.com",
        "phone": "(425) 555-0162 x4151"
    }
}
```

### Task 5: Review the run in detail

1. In the Azure portal, open your Logic App `logic-getsetting-<alias>-<unique>`.
2. Select **Overview** > **Run history**.
3. Select the most recent run.
4. Review each step:
   - **When a HTTP request is received** — shows the incoming request.
   - **Get blob content (V2)** — shows the blob path and retrieved content.
   - **Response** — shows the status code and response body sent back.

Checkpoint:

- You created a Logic App that reads a JSON file from Blob Storage.
- The Logic App returns the JSON content over HTTP.
- You can trace the full execution in the run history.

## Exercise 5: Review monitoring and diagnostics

Unlike Azure Functions where you see log output in the terminal, Logic Apps provide a visual run history and diagnostic experience in the Azure portal.

### Task 1: Review trigger history

1. Open any of your Logic Apps in the Azure portal.
2. In the Logic App menu, under **Development Tools**, select **Logic app designer**.
3. Select the trigger shape.
4. Select **See trigger history** (link at the bottom of the trigger card, or available from the trigger's context menu in some portal versions).
5. Review the list of trigger firings — each shows whether it resulted in a run.

### Task 2: Review metrics

1. In the Logic App menu, select **Metrics**.
2. Add a chart with the following settings:

   | Setting | Value |
   | --- | --- |
   | Metric | `Runs Completed` |
   | Aggregation | `Count` |

3. You should see data points for your successful runs.
4. Optionally add another metric: `Runs Failed` to confirm there are no failures.

Checkpoint:

- You explored the monitoring and diagnostic capabilities of Logic Apps.

## Troubleshooting

### Logic App trigger URL not showing

The HTTP POST/GET URL only appears after you save the Logic App with a Request trigger configured. Make sure you clicked **Save** in the designer toolbar.

### Blob Storage connection fails

Check:

- The storage account name is correct (no typos, all lowercase).
- The access key is correct and has not been regenerated since you created the connection.
- The storage account is in the same subscription as the Logic App.

To update the connection:

1. In the Azure portal, open your Logic App.
2. Select **API connections** from the Logic App menu (or find it in the resource group).
3. Open the blob connection.
4. Select **Edit API connection**.
5. Update the access key.
6. Select **Save**.

### Response returns empty body

Check:

- In the **Get blob content (V2)** action, the blob path is exactly `/content/settings.json`.
- The blob exists in the storage account (go to the container and verify).
- In the **Response** action, the Body field references **File Content** from dynamic content, not another field.

### Recurrence Logic App not running

Check:

- The Logic App is **Enabled** (not Disabled).
- The interval and frequency are set correctly (1 Minute).
- Wait at least 2 minutes after saving — the first run may not fire immediately.

### Run shows "Failed" status

1. Open the failed run from the run history.
2. Select the failed step (marked with a red X).
3. Expand the **Inputs** and **Outputs** sections to see the error details.
4. Common issues:
   - Expired or invalid connection credentials.
   - Blob not found (wrong path or container name).
   - Malformed expressions in Compose actions.
